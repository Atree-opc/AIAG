# [OPEN] domain-stale-deploy

## 症状
- 本地构建已包含最新修改，但通过域名访问时没有看到这些修改。

## 预期
- 域名访问应与当前项目最新部署内容一致，至少应包含最近完成的登录弱网提示和订单文件分组展示改动。

## 当前假设
- 假设 1：域名对应的服务进程没有重启，仍在运行旧的 `next start` 或旧容器。
- 假设 2：反向代理或域名配置指向了另一份项目目录/另一台服务，不是当前这份代码。
- 假设 3：当前服务器虽然重新构建过，但生产进程读取的是旧的 `.next` 产物。
- 假设 4：浏览器、Nginx 或 CDN 缓存命中了旧页面，导致域名看到的还是旧内容。
- 假设 5：域名访问的并不是本机 `localhost:3000` 这一路，而是另一端口或另一上游。

## 证据计划
- 对比本地代码与域名响应内容。
- 检查当前运行中的 Node/Next 进程、工作目录和启动命令。
- 检查反向代理配置与 upstream 目标。
- 必要时请求用户提供域名地址，以便直接抓取线上响应头和页面片段。
